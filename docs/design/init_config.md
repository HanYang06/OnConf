# 初始化配置

> **本页替换** DESIGN 的这几处：§9.1（把「隐式约定」当作换取「轻」的取舍 —— 该定性作废）、
> §15.1–§15.5（`op` 推断、`conf` 的 `**kwargs` 透传、单例可变的「必需品」定性）、
> §17.5（`conf` 只暴露四个参数）、§17.6（程序想持久化一个值怎么办）、
> §18.1 情形 4 的 `force` 例外、§29.2（`conf(key, doc=…)` 算读还是登记）。
> 旧稿在本页对应的设计全部落地后被删除；在那之前，**冲突时以本页为准**。

## 1. 两个面

对外只有两个入口，别的一律不是公开面：

| 面 | 职责 |
|---|---|
| `AutoConf(**engine)` | 配置**引擎自己**：配置目录、值文件类型、日志去向、审计、身份、锁超时 |
| `conf(key, value=…, doc=…)` | 干所有的活：读 / 写 / 登记 |

```python
from onconf import AutoConf, conf

AutoConf(home="./conf")   # 可省略 —— 省略时按约定找配置目录
conf("app.server.port", 8080)      # 声明 + 写；返回当前生效值
print(conf("app.server.port"))     # 读
```

**使用口不得配置引擎。** 以前 `conf("a.b", 1, home="/x")` 能顺带把引擎也配了，
现在是 `TypeError`：一个配置口、一个使用口，不靠「引擎是否已经起来」这种时序条件成立。

## 2. 引导层与值层

配置口分两层，这是本页最重要的一条：

| 层 | 内容 | 能不能运行中改 |
|---|---|---|
| **引导层** | `home` / `file_type` / `log` / `audit` / `identity` / `flush_window` / `lock_timeout` | **不能**。改了等于改代码，必须重启 |
| **值层** | 值文件里的一切 | 随便改 —— 值每次从文件重新读 |

引擎起来之后带参数再调 `AutoConf(...)` 会抛 `ConfError`：

```python
AutoConf(home="./conf")
conf("a.b", 1)
AutoConf(home="./other")   # ConfError：引导层不可运行中改
```

值层不受这条限制，因为文件才是事实：

```python
AutoConf(home="./conf")
conf("a.b", 1)
# 手改 ./conf/settings.json 里的 a.b，下一次 conf("a.b") 就读到新值
```

`AutoConf()` 不带参数调用**永远合法**，语义是「把单例取回来」。

## 3. `AutoConf` 的参数

参数清单只有一处权威：`onconf.EngineParams`。它既是类型提示也是运行时校验依据
（`AutoConf` 的注解与 `Engine.__init__` 的形参一一对应，有回归守着）。

| 参数 | 默认 | 说明 |
|---|---|---|
| `home` | `./conf` | 配置目录。显式参数优先，`ONCONF_HOME` 环境变量次之 |
| `file_type` | `""` | 值文件类型，**单值**。空串等价于 `"json"`，见[文件支持](file_support.md) |
| `log` | `"stderr"` | 强制日志的去向（`"stderr"` / `"stdout"` / 文件路径） |
| `audit` | `False` | 是否再追加一份 `<home>/audit.log` |
| `identity` | `""` | 写进每行记录的可选 `服务@主机` 标记 |
| `flush_window` | `0.0` | 攒批窗口（秒）。`0` = 每次声明当场落盘 |
| `lock_timeout` | `10.0` | 等 OS 锁的上限（秒） |

拼错的参数不会被吞掉：

```python
AutoConf(hme="./conf")   # UnknownEngineParamError（它同时是 TypeError）
```

## 4. 使用口的三种模式

模式**只看 `value` 位填没填**，不看这一行「在不在声明」：

| 模式 | 写法 | 判据 | 语义 | 返回 |
|---|---|---|---|---|
| 1 | `conf(key, value)`、`conf(key, value, doc)` | `value` 填了 | 声明 + 写 | 当前生效值 |
| 2 | `conf(key, doc=…)` | `value` 空、`doc` 给了 | 只登记（空结构） | 事实里的值；没有就报错 |
| 3 | `conf(key)` | `value` 空、`doc` 没给 | 读 | 文件值，其次词表默认值 |

```python
conf("app.port")                    # 模式 3：读
conf("app.port", 8080)              # 模式 1：声明 + 写
conf("app.port", 8080, "服务端口")   # 模式 1：第三个位置就是 doc
conf("app.port", doc="服务端口")     # 模式 2：只登记，随即取值
```

四条硬口径：

- **`None` / `""` / `0` 都是填了**，一律算模式 1；`MISSING` 是唯一哨兵。
- 第 2 位置恒属 `value`，所以 `conf(key, x)` 永远是模式 1；模式 2 只能由 `doc=` 触发。
- `doc` 是第三个**位置**参数，也是唯一的登记元数据。判据里不再出现第二个参数，
  所以参数面自此**封闭**：以后新增参数不需要动判据。
- `type=` 已取消（值类型由载体决定，见[文件支持](file_support.md)），
  `force=` 已取消（见下一节），`**engine` 已摘除。

### 报错口径

| 情形 | 结果 |
|---|---|
| 读未登记的键 | `KeyNotRegisteredError` |
| 已登记但事实里没有值 | `KeyHasNoValueError` |
| `key` 不是字符串 | `TypeError` |
| 传了已摘除的参数（`type=` / `force=` / `home=`…） | `TypeError` |
| 引导层参数在引擎起来之后改 | `ConfError` |

两类读错误必须分开，因为责任方不同：**键名写错了** vs **部署漏配了**。

## 5. 运行期的写路径：只补缺，不改已有

代码发出的写请求只做两件事：

1. **补缺**：期望有、事实没有 ⇒ 写进去；
2. **补元数据**：词表里的说明 / 默认值指纹与声明不一致 ⇒ 只更新词表。

对文件里**已经存在的值**，运行期一律只读：

```python
conf("app.port", 9090)   # 文件里已经是 8080（有人手改过）
                         # ⇒ 文件一个字节都不动，日志里记一条 op=skip
                         # ⇒ 返回的是 8080（当前生效值），不是 9090
```

**为什么没有覆盖出口**：配置是用户的持久状态，代码只能「补它没有的」，不能
「改它已经有的」。这是「文件是绝对权威」的直接推论 —— 如果代码能覆盖文件，
那文件的权威就是可撤销的，「文件优先」就不再是铁律，只是个默认值。
`force=True` 曾经是这个例外口子，已随本口径取消。

> 旧稿的 §17.6 问「程序想持久化一个值怎么办」，答案是：**不做**。
> 程序故意改一个已存在的值，越过了「配置属于用户行为」这条线。

## 6. 收敛与清理归命令行

「把值文件收敛到与声明一致」（含覆盖旧值）和「删掉代码未声明的键」都是**人主动
发起**的动作，不属于代码的写路径：

| 路径 | 发起方 | 做什么 |
|---|---|---|
| 导入即执行（本库） | 程序 | 只补缺 + 补元数据 |
| `onconf build` | 人 | 加载并执行声明代码，把值收敛到与声明一致；不删任何键 |
| `onconf sync` | 人 | 离线、单次、全量执行，收敛**并删除**未声明的键 |

判据不是「能不能覆盖」，而是「**谁发起**」：程序发起只补缺，人发起才可以收敛。

> `build` / `sync` 属命令行体系（ISSUE-031），**当前尚未实现**；键的清理移出
> 运行期是 ISSUE-035，也尚未落地 —— 在那之前，`sync()` / 进程退出仍会清理
> 未声明的键。本页只描述目标口径。

## 7. 目录约定

```text
<home>/settings.json          值文件（用户手改）；后缀由 file_type 决定
<home>/schema/settings.json   词表（**库自己的资产**，随便重写）
<home>/schema/settings.lock   锁的握手点（空文件；库自己的簿记）
<home>/schema/settings.key    写者端点的认证码（0600；库自己的簿记）
<home>/audit.log              审计文件（append-only；audit=True 才有）
```

- `home` 缺省从「当前目录」改成 **`./conf`**，与 DESIGN §9.1 的字面一致；
  `ONCONF_HOME` 仍然可以把它指到任何地方。
- 文件名主干固定 `settings`；后缀由 `file_type` 决定，不再「按存在性挑第一个」。
