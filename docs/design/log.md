# 日志

> 本页是**日志**的设计口径：**一份记录流、两个出口、三个口子**。
> 「审计」不是另一件东西 —— 落盘的那一份就是审计，它就是文件出口。
>
> 使用口见[初始化配置](init_config.md)，谁能写、读会看到什么见[并发模型](concurrency.md)。

## 1. 一句话

**记录只有一份，出口有两个；文件出口没有开关，控制台出口有一个。**

| 出口 | 开关 | 形态 |
|---|---|---|
| **文件** | **没有**（恒写） | 紧凑 `key=value`、全量、永不截断、只追加 |
| **控制台** | `log_console`（默认开） | 人读表格、按显示宽度截断、TTY 上着色 |

两个出口同源，所以不会出现「文件里写的和终端上说的不是一回事」。

## 2. 记录流

级别五个 —— 配置事实四个，加一行启动：

| 级别 | 什么时候出现 |
|---|---|
| `[Read]` | 读一个键（同一事务内重复读合并成一行 `n=<次数>`） |
| `[Write]` | 一次对账动作，`op=` 取 `fill` / `register` / `update_meta` / `skip` / `noop` |
| `[Change]` | 值真的变了（`old=` → `new=`） |
| `[Error]` | 一次失败（键名错、部署漏配、落盘失败……） |
| `[Start]` | 引擎起来了（`pid` / `id=` / 值文件名） |

`[Start]` 是唯一的生命周期记录，且**立即输出**：它描述的是「此刻这个进程在干什么」，
攒着就失去意义。其余记录攒在事务里，等提交点（写提交 / `flush()` / `sync()` / 进程退出）
一起出去 —— 代价写明：**纯读的程序在退出前看不到自己的行**。

**谁发起谁记账**：没有第二个执行点，所以 `pid` / `id=` / `at=` 全部取自本进程。

## 3. 文件出口

- **恒写**：引擎实例一旦跑起来就写，第一行是 `[Start]`，没有参数能关掉它。
- **落点**：`log_path`，缺省是**伴随值文件目录**的 `<home>/audit.log`；给了相对路径就按
  `<home>` 解析。
- **父目录不由审计创建**：建 `<home>` 属于值文件写入那条路。父目录不存在 ⇒ 审计失败、
  当场报错 —— 打错 `home` 应当立刻可见，而不是凭空造出一棵目录树。
- **只追加**（`O_APPEND`）、**以 `0600` 创建**、**永不截断**、字段是**白名单**
  （不是把值对象整个 dump 出去）。
- **写不出去是有代价的**：抛 `ConfError`。唯一例外是 `[Start]` 这类信息性记录 ——
  它不该拦住第一次 `conf()`。

**恒写的代价写在这里**：引擎实例以 `<home>` 可写为前提，只读挂载上连读配置都会失败。
不产生记录的只读路径（命令行 `check`）不建实例，因此不落盘 —— 那是「没有记录」，不是
「有个开关把它关了」。

## 4. 控制台出口

- `log_console=False` 关掉；`stderr` 是唯一去向 —— 库日志不占 `stdout`，那是调用方的
  数据通道。
- **TTY 上走 `rich`**，且在终端渲染分支**惰性导入**（`import onconf` 不碰它）；
  **非 TTY 走纯文本**。两条路都不输出 ANSI，非 TTY 那条要求逐字稳定。
- **宽度与截断自己算**，不用自动折行：审计行是定宽表格，折行会把对齐毁掉。`rich`
  只负责着色。
- **不做级别筛选**：控制台要么开、要么关。

## 5. 三个口子

默认全是「不做」—— 不轮转、不脱敏、不编码。要什么自己塞进来：

| 参数 | 拿到什么 | 返回什么 |
|---|---|---|
| `log_rotate` | 当前落点、已写字节数 | **这一批写到哪个文件** |
| `log_scrub` | 一条记录 | 一条记录（脱敏后的） |
| `log_encode` | 渲染后的字节 | 落盘字节（加密 / 压缩） |

**轮转是「换落点」，不是「搬文件」**：策略返回新路径，引擎换一个文件继续追加，
**绝不 `rename` 已经在写的文件**。理由是并发 —— 改名会让已经写下的审计在别的进程眼里
凭空消失，换落点只影响接下来写哪儿。默认 `None` ⇒ 一个文件一直长，长到什么程度由你定。

**脱敏与加密都不提供实现**：引擎不知道哪些值敏感，也不该猜。`log_scrub` 在落盘前改掉
任意字段，`log_encode` 决定最终的字节形态（明文、密文、压缩包都行）。密钥由调用方给，
**引擎不生成、不推导、不保管**。

## 6. 参数面

日志组（全是引导层参数，运行中不可改）：

| 参数 | 缺省 | 语义 |
|---|---|---|
| `log_path` | `""` | 文件出口落点；空串 = `<home>/audit.log`，相对路径按 `<home>` 解析 |
| `log_console` | `True` | 控制台出口开关 |
| `log_rotate` | `None` | 轮转策略（换落点） |
| `log_scrub` | `None` | 脱敏钩子 |
| `log_encode` | `None` | 落盘编码钩子 |
| `identity` | `""` | 每行带的 `id=` |

**没有 `audit` 开关**：文件出口恒写，不需要一个布尔量来表态。

## 7. 多进程与命令行

文件出口（以及用户自己开的轮转落点）**可能被多个进程同时追加**，那是预期的：

- 每行自带 `pid=` 与 `txn=`；**`txn` 是每进程自增的**，两个进程可能撞号，解析者按
  `pid` 分桶；
- 追加走 `O_APPEND`，一批一次 `write`，所以每次落盘是完整的一批；
- 引擎不搬动审计文件 ⇒ 默认路径上没有「改名撞车」这种失败模式。用户自己写的策略要
  自己保证同样的性质。

命令行是**发起方**，也是执行点：`build` / `sync` 的记录走同一份出口。`check` 走不产生
记录的只读路径，因此不落盘、不建目录。

## 8. 不变量

1. 记录只有一份，两个出口同源；
2. 文件出口恒写、只追加、`0600`、永不截断、字段白名单；
3. 引擎不搬动已经写下的审计文件；
4. 文件出口写不出去要出声，控制台出口写不出去不阻断配置读写；
5. `import onconf` 不导入 `rich`，非 TTY 输出无 ANSI。
