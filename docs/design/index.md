# 设计稿索引

本页范围：说明 `docs/design/DESIGN.md` 是一份什么样的文档、建议怎么读。

⏳ 正文待补：等设计定稿后补齐。本页后续只做阅读引导与背景说明，
**不复制设计稿的正文**，也不把设计愿景当成既成能力。

## 这份文档是什么

- **位置**：`docs/design/DESIGN.md`，是设计内容在仓库里的唯一归属。
- **性质**：**未定稿的设计草案**。文件标题即写明「设计草案 v0.1」，正文里既有带 ❓ 的待拍板项，
  也有被后续小节明确推翻的前期结论（例如 §11 开头写着「本节结论取代 §9 的第 1 条」）。
- **因此**：设计稿里出现的能力**不等于**已实现的能力。哪些能用、哪些还不能用，
  以[路线图](../roadmap.md)的「已实现 / 进行中 / 未实现」三段为准。

## 建议阅读顺序

1. **§1 定位** —— 这个库到底解决什么问题、不解决什么问题。
2. **§2 能力清单** —— 打算做什么，以及明确不做什么。
3. **§3 地基：键空间与词表** —— 后面所有讨论共用的词汇表（键、词表、事实）。
4. **§17 事实权威：文件绝对优先** —— 核心语义。读任何实现之前先读这一节。
5. **§29 引擎装配收口** —— 实现期才暴露的三个发现，直接解释 v1 为什么是现在这样。

## 关于阅读方式的提醒

设计稿里有**实测数据**（启动成本、WAL 追加耗时、`os.replace` 全量替换耗时等），
它们的测量环境写在相应小节的标题或表头里；脱离那个环境引用这些数字会失真。
