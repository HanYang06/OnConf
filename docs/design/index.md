# 设计稿索引

本页范围：说明 `docs/design/` 下有哪些设计文档、建议怎么读。

⏳ 正文待补：等设计定稿后补齐。本页后续只做阅读引导与背景说明，
**不复制设计稿的正文**，也不把设计愿景当成既成能力。

## 目录

| 文档 | 管什么 |
|---|---|
| [初始化配置](init_config.md) | 两个面、`AutoConf` 的参数、`conf` 的三种模式、运行期写路径、目录约定 |
| [文件支持](file_support.md) | 值文件选定（`file_name` / `file_type`）、返回值口径、四个后端、词表、外科手术式回写 |
| [并发模型](concurrency.md) | 实例与寻址、属主 / 派生角色、那条唯一的禁令、引擎明确不做的事 |
| [日志](log.md) | 一份记录流、两个出口、三个口子（轮转 / 脱敏 / 编码） |
| [命令行](cli.md) | 命令矩阵：九条命令的语义与分工、统一约定、退出码、与运行中进程的关系 |

## 这几份的关系

`init_config.md` 管「配置面怎么用」，`file_support.md` 管「值落在哪个文件的什么形态」，
`concurrency.md` 管「谁能写、读看到什么」，`log.md` 管「记录在哪儿、能开什么口子」，
`cli.md` 管「哪些命令存在、每一条写不写字节、它跟运行中的进程什么关系」。
它们同时是**使用说明** —— 想知道怎么调，看它们就够了。

## 关于「能不能用」

设计文档里出现的能力**不等于**已实现的能力。范围与版本以[路线图](../roadmap/README.md)为
**唯一裁决**：设计稿与路线图不一致时改设计稿，实测证明路线图不成立时改路线图的条目状态。
[1.0.x](../roadmap/1.0.x/roadmap.md) 是已发布那一版的冻结记录。
每份设计稿末尾都有一节「还没落地的部分」，逐条列出它与实现之间的已知差异。

## 关于阅读方式的提醒

实测数据（启动成本、WAL 追加耗时、`os.replace` 全量替换耗时等）都写在对应小节的标题或
表头里；脱离那个测量环境引用这些数字会失真。
