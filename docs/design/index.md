# 设计稿索引

本页范围：说明 `docs/design/` 下有哪些设计文档、建议怎么读。

⏳ 正文待补：等设计定稿后补齐。本页后续只做阅读引导与背景说明，
**不复制设计稿的正文**，也不把设计愿景当成既成能力。

| 文档 | 管什么 |

## 这两类文档的关系

旧稿 `DESIGN.md` 是一份「规格 + 决策日志」混在一起的文档：正文里既有带 ❓ 的待拍板项，
也有被后续小节明确推翻的前期结论。新的做法是**逐步替换**：

1. 每份新文档在开头写明它**替换旧稿的哪几节**；
2. 该文档对应的设计全部落地后，旧稿里的那几节随之退役；
3. 等所有新文档都写完，`DESIGN.md` 整体删除。

**因此冲突时以新文档为准。** 新文档同时是**使用说明** —— 想知道怎么调，
看新文档就够了，不需要再翻旧稿。

## 关于「能不能用」

设计文档里出现的能力**不等于**已实现的能力。哪些能用、哪些还不能用，
以[路线图](../roadmap.md)的「已实现 / 进行中 / 未实现」三段为准；
每份新文档末尾都有一节「还没落地的部分」，逐条列出它与实现之间的已知差异。

## 关于阅读方式的提醒

旧稿里有**实测数据**（启动成本、WAL 追加耗时、`os.replace` 全量替换耗时等），
它们的测量环境写在相应小节的标题或表头里；脱离那个环境引用这些数字会失真。
