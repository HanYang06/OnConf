## 1. 值从哪个文件来：`file_name` + `file_type`

引擎一次只用一个类型。**用哪个文件是显式声明的**：

```text
目录      <home>                       ← 参数（缺省 ./conf）
文件名称  file_name = "settings"       ← 参数：单值，纯文件名
文件类型  file_type  = "json"          ← 参数：单值，取值与后缀一一对应
文件路径  <home>/<file_name><ext>      ← 由上面三者派生
```

| `file_name` | `file_type` | 实际文件 | 后端 |
|---|---|---|---|
| `"settings"`（缺省） | `"json"`（缺省） | `settings.json` | JSON |
| 任意纯文件名 | `"json"` / `"yaml"` / `"yml"` / `"toml"` / `"env"` | `<file_name>.<ext>` | 对应后端 |

```python
AutoConf(home="./conf")                              # → ./conf/settings.json
AutoConf(home="./conf", file_name="app")             # → ./conf/app.json
AutoConf(home="./conf", file_name="app", file_type="toml")  # → ./conf/app.toml
```

- **缺省值是字面的 `"json"`**：默认值只有一个来源，不靠空串隐含语义；`""` 不是合法取值
  （D01 §5：`file_type` 的缺省与「本质上以 JSON 为主」绑定）。
- 取名或取值不合法都当场抛 `ConfError`；`file_type` 的消息里列出全部合法取值。
- `file_name` 必须是**纯文件名**：过包含性校验，见 §1.1 与[路径安全](../security/threat-model.md)的 T1。
- 目录里恰好有别的类型文件**不会**被选中。「按存在性从候选名里挑第一个」已退役 ——
  那是把「哪个文件生效」交给磁盘上恰好有什么，属于隐式约定。

### 1.1 多文件：`no_one_file`

`no_one_file=True`（缺省 `False`）打开键内嵌路径：键里**第一个** `:` 的左边是相对路径、
右边是文件内的键名。

```python
AutoConf(home="./conf", no_one_file=True)
conf("app/conf/net:net.id.post", 8080)   # → ./conf/app/conf/net.json 里的 net.id.post
conf("plain.key", 1)                     # 没有 ':' ⇒ 仍落到 ./conf/settings.json
```

| 项 | 取值 |
|---|---|
| 没有 `:` 的键 | 落到默认文件 `<home>/<file_name><ext>` —— 单文件与多文件可以混用 |
| 词表 | **只有一份**：`<home>/schema/<file_name>.json`；每个值文件的 `$schema` 指针按自己的层级算相对路径 |
| 锁与写者 | 仍然每个 `<home>` + `<file_name>` 一个 |
| 归引擎管的文件 | **默认文件 + 当前声明集引用到的路径段**；磁盘上其它值文件一个字节都不动（也不会被规则 1 清理） |
| 路径安全 | 路径段必须过包含性校验：相对、无 `\\`、无 `.` / `..` / 空段、非绝对、解析后仍在 `<home>` 之内 |
| 多文件关闭 | `:` 不参与任何解析，整个字符串就是一个普通键 —— 与多文件开启前行为完全一致 |

命名空间形式（`file_names = []`）留待后续版本；**同一个键在不同文件里同名不冲突**，
因为词表记的是全键（含路径段）。

### 新建文件时从「种子」起步

新建一个值文件时，引擎先向后端要一段**种子文本**，再往里插第一个键：

| 后端 | 种子 | 为什么 |
|---|---|---|
| JSON | `{}` | 空文本连 `{` 都没有，插不进成员 |
| YAML / TOML / `.env` | 空文本 | 空文件本身就是合法骨架 |

## 2. 读回来的是什么：载体原生类型

**「可直推」的准确含义是载体自己带着类型信息**：载体能表达就返回，不能表达时按字符串。
引擎只把解析结果原样交出。

| 后端 | 载体能表达 | 读回来 |
|---|---|---|
| JSON | string / number / boolean / null / array / object | 对应的 Python 类型；`dict` / `list` 正常返回 |
| YAML | 同 JSON（YAML 1.2 是 JSON 超集） | 同上 |
| TOML | string / integer / float / boolean / array / table / datetime | 同上；`None` 表达不了，写 `None` 当场报错 |
| `.env` | 只有字符串 | 一律 `str` |

载体的**显式类型标签被尊重**：YAML 的 `!!str "8080"` 读回字符串 `"8080"`，
标签由 `yaml.safe_load_all` 解析，引擎原样交出。

## 3. 引擎的三个「不做」

1. **不从内容猜类型**：`PORT=8080` 在 `.env` 上读回 `"8080"`，不变成 `int`；
2. **不做向声明类型的转换**：要 `int` 就在使用处写 `int(conf("PORT"))`；
3. **不为缺失的载体能力兜底**：`.env` 里的复杂结构就是字符串。

类型声明（`conf(..., type=int)`）已整体取消：词表不再记类型，声明期校验、
`TypeConflictError`、JSON Schema 的 `type` 与 `x-onconf-py` 扩展一并作废。
要数字就在调用点显式写 `int(…)` —— 这样「哪里发生了转换」在代码里一眼可见。

## 4. 跨后端类型差异不承诺可移植

同一个键在不同后端可以读回不同类型，这条差异**不进词表**，只写在文档里：

```python
conf("app.tags")   # JSON 后端 → ["a", "b"]
conf("app.tags")   # .env 后端 → "['a', 'b']"（如果开了结构开关）
```

## 5. 后端能力与支持计划

**本质上以 JSON 为主**：它是缺省值，也是能力最完整的一份。其余后端是**可选后端**，
不是并列默认。

| 后端 | 状态 | 备注 |
|---|---|---|
| JSON | **主后端**，1.0 起 | 能放 `$schema` 成员；编辑器补全的落点 |
| YAML | 可选，1.0 起 | 注释、锚点、键序都原样保留；能放 `$schema` 成员 |
| TOML | 可选，1.0 起 | 表头归一到点分键；没有 `null`；放不下 `$schema` 成员 |
| `.env` | 可选，1.0 起（**字符串标量**） | 不做类型推断、不认行内注释、不做键名映射；放不下 `$schema` 成员 |
| `.env` 的 `dict` / `list` | **计划中，预计 2.2** | 由 `env_file_dict` / `env_file_list` 两个布尔开关显式开启，默认关；开启后写入压成字符串、读取尝试解回、解不回就返回字符串 |
| 多文件（键内嵌路径） | **已实现**（`no_one_file`） | `conf("app/conf/net:net.id.post")`；与包含性校验同批落地，见 §1.1 |
| 命名空间形式（`file_names = []`） | 计划中，版本待定 | 多文件之上再按命名空间分组；当前只有「路径段」一种分组 |

> 「预计 2.2」是排期意向，不是承诺；落地时以 [路线图](../roadmap.md) 的状态行为准。

## 6. 词表

词表是**库自己的资产**，与任何一份代码无关地持久化在 `<home>/schema/<file_name>.json`
（缺省即 `<home>/schema/settings.json`；多文件模式下**仍然只有这一份**）。
它只记三样东西：

| 字段 | 含义 |
|---|---|
| 键 | 有哪些键是**词表**说了算 |
| `description` | 登记时给的说明（`conf(..., doc=…)`） |
| `default` | 默认值指纹；**键缺失**表示「登记了但没有值」，`"default": null` 表示「值就是 null」 |

那三种状态不许塌陷 —— 前者的读会报 `KeyHasNoValueError`，后者返回 `None`。
顶层另有一个 `x-onconf-hash`：声明集指纹，用于「对得上就整体跳过写入」的脏检查
（它是脏检查，不是锁：对不上只意味着这一次短路不成立）。

**归属权**：值文件的主人是用户（手改它、保留注释与缩进），词表是库自己的产物
（整篇重写合法，不需要外科手术）。这条分界是「未触及的字节逐字不动」能成立的前提。

**旧文件兼容**：旧词表里可能还留着 `type` / `x-onconf-py`，读入时直接忽略；
下一次落盘不再写它们，文件自然收敛到新形态。

## 7. 外科手术式回写

值文件的回写只碰该碰的字节：注释、缩进、键序、空行、行尾都逐字保留。

四个后端各提供同一组操作：`loads` / `iter_members` / `find` / `set_value` /
`append_key` / `delete_key` / `render`，外加一个 `EMPTY_TEXT` 种子。

**运行期只会用到 `append_key`**：值不一致时尊重文件（`op=skip`），所以「替换一个
已存在键的值」（`set_value`）在运行期没有驱动者 —— 它是留给命令行收敛动作的，
现在由各后端的单元测试直接覆盖。

## 8. 指令键与 `$schema` 指针

`$` 开头的键是**指令**，不是配置项：不参与对账（否则规则 1 第一次运行就会把
`$schema` 删掉），也不许被声明。

值文件必须带 `$schema` 指向词表，编辑器才知道去哪补全。这条**不是新建时才补，
是每次落盘都保证有**：

```jsonc
// ./conf/settings.json —— 用户手改的那份
{
  "$schema": "schema/settings.json",
  "app.server.port": 8080
}
```

`.env` / `.toml` **放不下成员**（硬塞只会让文件变成语法错误），所以这两个后端跳过
指针注入。TOML 侧另有 Taplo 的 `#:schema` 注释指令，留待后续。

## 9. `.env` 是字符串后端

这一条必须说在前面：`.env` 物理上只能存字符串，所以它**不参与**「写出去什么、
读回来还是它」这条保证。与其假装能做到，不如当场拒绝：

```python
conf("PORT", 8080)   # TypeError：.env 只能存字符串；要存非字符串请改用 JSON / YAML
```

两处与 YAML 后端刻意的不同：

1. **不认行内注释**。`#` 只在整行（前面只有空白）时才是注释 ——
   `.env` 里放密码是常态，`PASSWORD=abc#def` 的 `#` 是值的一部分。
2. **不做键名转换**。键就是文件里写的那个名字（`pack.max.byte=1` 或
   `PACK_MAX_BYTE=1` 都行，不作映射）。有损的 `.` ↔ `_` 映射留给词表的显式映射，
   不在后端里猜。
