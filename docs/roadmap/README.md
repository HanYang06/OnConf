# 路线图读法

> 本目录是**范围与版本的唯一裁决**：定「做什么、按哪套设计、落在哪个版本」，设计与代码
> 都往它收。**它不宣布现状** —— 「现在能用什么」由仓库根 `README.md` 的能力表与
> `CHANGELOG.md` 回答。
>
> 参与变更决策作者：[@HanYang06](https://github.com/HanYang06)

## 目录

| 文件 | 装什么 |
|---|---|
| 本页 | 原则、规矩、策略：三层口径、收录原则、卡片与编号、勾选框与版本状态 |
| [`1.0.x/roadmap.md`](1.0.x/roadmap.md) | 1.x 线，随 v1.0.0 发布**冻结**，只读 |
| [`2.x.md`](2.x.md) | 2.x 线的条目与版本分配（当前） |
| `3.x.md` … | 以后每开一条大版本线加一份 |

**一个大版本线一份文件，一份文件里再分小版本。** 一条线发完，那份文件整份冻结
（`1.0.x/roadmap.md` 就是），此后只读。

**地址只增不改。** 路线图路径改一次就要留一个跳转页 —— `1.0.x/`、`2.0.x/` 两个旧地址
就是这么留下来的（`CHANGELOG.md` 与已发布的那条线引用着它们）。所以命名一次定死：
之后**只加文件，不改名、不加子目录**。

## 三层口径：路线图 > 设计 > 代码

| 层 | 管什么 |
|---|---|
| 路线图（本目录） | 做什么、按哪套设计、落在哪个版本 —— 条目卡片 |
| [`docs/design/`](../design/index.md) | 为什么这么做、边界在哪 |
| 代码 | 实际跑成什么样 |

- **说法冲突**（同一件事在三层之间说得不一样）⇒ 改下层；
- **事实冲突**（实测、事故或部署现实证明上层不成立）⇒ 改上层，而改上层只有两种动作：
  **新增条目**，或**撤回条目的 `决策状态`**（`已定` → `待裁` / `已废弃`，写明理由与影响面）。

**条目只增不减、版本号只增不减、编号不复用** —— 这条不可逆性是原则能成立的前提，
否则它只是最高权力。

## 收录原则

**主动开发才进路线图；修复不进。**

| 这一改是什么 | 去哪儿 |
|---|---|
| 当前设计的**实现**错了 | 不进路线图；进 `CHANGELOG.md`，走 patch 版本 |
| **设计本身**错了，或者范围变了 | 它已经不是修复，是**下一个小版本的内容** ⇒ 进路线图 |
| 改变了**公开契约**（API / 磁盘格式 / 安全语义） | 必进路线图，哪怕它是打着 `fix:` 合进来的 |

判据不是「这次提交叫什么」，而是**问题出在实现还是设计**。这三条不用另立规矩 —— 它们就是
[语义化版本](https://semver.org/lang/zh-CN/)的映射：修复走 patch，范围与设计走 minor / major。
**小版本号由范围批次驱动，不由修复数量驱动**，所以 `2.34367.2675` 这种事不会发生。

两条边界：

- **安全修复**若必须改契约，可以走 patch，但**同时要立一条下一版的条目** —— 修了不等于口径就对了；
- **同一个地方反复坏**说明设计缺一块：按「设计错」处理，立一条条目，而不是继续修。

修复史由 `CHANGELOG.md` 承担（发布说明由 `.github/release-drafter.yml` 从 PR 标题与标签生成），
所以它必须是**真的修复史**：每个 `fix:` 的 PR 都要在「未发布」段落里留一行。

## 条目卡片

每个条目固定六行，**缺项留空不删** —— 字段是栏位，不是正文：

```text
> 路线ID:
> 决策状态:
> 设计关联文件:
> 分配实现版本:
> 具体实现文件:
> 关联 issues / PR:
```

- `决策状态`：`已定` / `待裁` / `未定` / `未来项` / `已废弃`；破折号后接该状态的具体所指。
  这一栏说的是**决策**，不是进度。
- `设计关联文件`：设计口径在哪一页。`docs/` 内用相对链接；仓库根的文件用反引号路径。
- `分配实现版本`：`2.0.0` / `2.1.0` / …；未定写 `待定`，废弃写 `已废弃`。
  **patch 版本不进这一栏。**
- `具体实现文件`：代码落在哪；尚未建就写明缺哪一层，**不写「无」**。
- `关联 issues / PR`：GitHub 编号；尚未合并的标 `未合`。

## 编号

**前缀就是版本线**：`2-001`、`2-002`…；下一条线从 `3-001` 起。

- 前缀 = 文件 = 大版本线 ⇒ 天然全局唯一，**不需要任何地方登记「下一个号」**；
- **顺序发号、号不复用**：条目改名不改号，条目废弃也不回收号；
- 引用写成「路线图 `2-021`」，指向条目所在的那份文件。

## 勾选框与版本状态

- `- [x]` 表示这条**不在待办里** —— 收口了，或是废弃了；两种情形靠括号分辨：**收口**不加注，
  **废弃**在条目名后注 `（已废弃）`。
- **废弃不删**：曾经定过、现已不再做、且代码与设计都已清空的条目留着并打勾，汇总在本线的
  `### 已废弃`，不占版本号 —— 留痕是为了后人不再重新提一遍。用来记录「决定不做」的设计稿
  不算「有设计」。
- **版本只有两种状态**：**已发布**（标题后注 `（已发布）`，写死、此后不再变动）与
  **未落定路线**（注 `（未落定路线）`，或什么都不写）。改分配是**纯增量**，不视为推翻。
