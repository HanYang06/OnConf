> 本页只管 **2.0 这一版**：收什么、每条决策定成什么样、还差什么、哪些问题要你拍板。
> 不写编号考古（原 `docs/issues/` 的 12 个决策单元与三份诊断已删除，要追溯逐条证据看
> git 历史），也不抄已经发布的 1.0 面 —— 那是 [1.0.x](../1.0.x/roadmap.md)。
>
> 每条四段：**标题 / 正文 / 状态 / 引用设计文稿**。
> 状态词：`已实现（待发版）` = 主线上代码已经改完、还没打 tag；`待实现`；`待裁`；
> `不计划`；`已定不动` = 口径已经定死，本版不改也不做。

## 0. 这一版的范围与顺序

**2.0 只收四根柱子**，其余一律不进 —— 有下游项目在等这个版本，范围优先于完整。

**柱一 · 配置面 / API 面**：`conf` 收敛成三种模式；`file_name` / `file_type` / `no_one_file`
三个参数；删掉类型声明；外部字符串进路径只走包含性校验；使用范式成文。
**不收**：`.env` 的结构化值（`dict` / `list`）。

**柱二 · 进程结构**：写者从「住在客户进程里的线程」改成**独立 Alpha 进程** ——
按需拉起、短命、由 `AutoConf` 自举、所有等待有上界；运行期不再清理未声明的键。
**不收**：读路由「量大」的参数化、数据交付边界。

**柱三 · 审核日志**：文件通道**强制全量**、终端通道**可关、可按级别筛**、
审计**恒写**、审计路径由独立参数给。**不收**：落盘四形式（明文 / 二进制 / 加密）
与轮转三组参数。

**柱四 · 命令行**：`build` / `sync` 已交付；本版补 `check` / `get` / `read` / `set` /
`diff` / `format`（`format` 只做 JSON）。**不收**：`add`（生成声明代码）、
`remove`（单键删除）、日志分析视图。

**顺序（依赖驱动，不按编号）**：

```text
环境变量层的口径（柱一收尾）
  → 独立 Alpha（柱二，关键路径、最重）
    → 日志两通道（柱三，「终端回传发起方」那半依赖柱二的执行点）
      → 命令行余项（柱四，依赖执行点与日志）
        → 发版：迁移说明 + CHANGELOG + README 状态表
```

**破坏性变更**（要进 CHANGELOG 与迁移说明）：`conf` 签名收敛；`type=` / `force=` /
`conf(..., **engine)` 三处删除；`file_type` 的缺省值与空串语义；`home` 缺省从「当前目录」
改成 `./conf`；值文件选定不再「按存在性挑第一个」；多文件开关；运行期不清理未声明的键；
日志两通道与 `audit` 开关取消；写者由进程内线程改成独立 Alpha。

## 1. 柱一 · 配置面 / API 面

### 1.1 使用口收敛成三种模式

`conf(key, value=MISSING, doc=None)`：`conf(key)` 读；`conf(key, value)` 声明 + 写；
`conf(key, value, doc)` 声明 + 写 + 登记说明；`conf(key, doc=…)` 只登记（空结构）
随即按读规则取值。判据**只看 `value` 位填没填** —— `None` / `""` / `0` 都算填了，
`MISSING` 是唯一哨兵。判据只有这一条，所以参数面是封闭的：再加参数也不用动它。

**状态**：`已实现（待发版）` ｜ **引用设计文稿**：[`init_config.md` §4](../../design/init_config.md)

### 1.2 报错与返回值口径

读未登记 ⇒ `KeyNotRegisteredError`；已登记但事实里没有值 ⇒ `KeyHasNoValueError`；
声明 + 写返回**事实里的值**（不是传入的默认值）；`key` 不是字符串 ⇒ `TypeError`。
两类读取错误的责任方不同：键名写错 vs 部署漏配。

**状态**：`已实现（待发版）` ｜ **引用设计文稿**：[`init_config.md` §4](../../design/init_config.md)

### 1.3 没有类型声明

使用口**不接受类型声明**：`Decl` 与 `VocabEntry` 只有键、说明、默认值，`conf(key, type=int)`
抛 `TypeError`。词表退化为「**键 + 说明 + 默认值**」，JSON Schema 不写逐键 `type` 与
`x-onconf-py`（Schema 顶层 `"type": "object"` 保留）。类型也不参与任何持久状态：
声明集哈希不编码类型，声明期不做校验。要转换就在调用点写 `int(conf("PORT"))`。

**状态**：`已实现（待发版）` ｜ **引用设计文稿**：[`file_support.md` §6](../../design/file_support.md)、
[§3 三个「不做」](../../design/file_support.md)

### 1.4 运行期只补缺，覆盖归人

`conf` **没有覆盖既存值的参数**：模式 1 撞上文件里已有的不同值时按「尊重文件」处理
（记一条 `op=skip`，值文件逐字不动）。覆盖既存值只由**人**发起：`onconf build`
按声明完整重建值文件与词表（`--path` 换输出目录、原目录不动）；`onconf sync`
只补缺 + 更新词表 + 删除未声明的键，**不覆盖既存值**。判据不是「能不能覆盖」，
而是「**谁发起**」。

**状态**：`已实现（待发版）` ｜ **引用设计文稿**：[`init_config.md` §5 / §6](../../design/init_config.md)

### 1.5 使用口不得配置引擎

`conf` **不接受引擎参数**：`conf(..., home=…)` 这类调用抛 `TypeError`，不静默降级。
理由是「一个配置口、一个使用口」不该依赖「引擎是否已经起来」这个时序条件。

**状态**：`已实现（待发版）` ｜ **引用设计文稿**：[`init_config.md` §1 / §2](../../design/init_config.md)

### 1.6 使用范式：声明处必须字面量

**声明形态**（`value` 位填了的调用）的键、值与说明都必须是**字面量**；**读取不受限制**
（常量、拼接都行，错了当场 `KeyNotRegisteredError`）。非字面量实参（`APP_POST = "app.post"`、
循环、表达式）**不在支持范围内**：不解读、不求值，一律进问题清单，唯一承诺是「不静默丢」。

**不设门禁** —— Python 合法、在本库不合理，error 的分界是「不合法」；只在文档里写清代价：
命令行静态扫描看不见它（`sync` 因此拒绝删除任何键，可加 `--no-clean`）、`grep` 覆盖不到、
声明点不再自证。未来 `check` 按同一判据出 **warning**。

**状态**：`已实现（待发版）`（文档与口径）；`check` 的 warning 仍 `待实现`
｜ **引用设计文稿**：[`init_config.md` §8](../../design/init_config.md)

### 1.7 `file_name` 与 `file_type`

文件名主干由 `file_name` 给（**纯文件名**，缺省 `settings`，可显式指定）；
`file_type` 是**单值**参数，决定实际使用的后端与后缀，缺省是**字面 `"json"`**，
`""` 不是合法取值（抛 `ConfError`）。值文件路径 `<home>/<file_name><ext>` 是派生的。
`home` 缺省是 `./conf`。生效文件只由这两个参数决定，与磁盘上恰好有什么无关。

**状态**：`已实现（待发版）` ｜ **引用设计文稿**：[`file_support.md` §1](../../design/file_support.md)

### 1.8 多文件：一个开关 + 键内嵌路径

多文件就是 `no_one_file`（缺省 `False`）。关闭时键就是一整串普通字符，`:` 一个字节都不解析；
开启时把**第一个** `:` 左侧解析成文件路径：`conf("app/conf/net:net.id.post", 8080)` →
`<home>/app/conf/net.json`、文件内键 `net.id.post`；后缀由 `file_type` 决定，键里不写扩展名。
没有 `:` 的键仍落**默认文件**，单文件与多文件可以混用。层级只发生在**文件之间**，
文件内部键仍扁平。只认 `/`；路径段里出现 `\` 直接拒绝。

**不去枚举文件** —— 归引擎管的文件 = 默认文件 + 当前声明集引用到的路径段；
磁盘上其它值文件不加载、不清理。一份总词表 `<home>/schema/<file_name>.json`，
每个值文件的 `$schema` 指针按自己的层级算相对路径。

**状态**：`已实现（待发版）` ｜ **引用设计文稿**：[`file_support.md` §1.1](../../design/file_support.md)

### 1.9 包含性校验：外部字符串进路径的唯一入口

目的是「键名不得把写入带出 `home` 之外」（威胁模型 T1）；手段从**固定白名单**改成
**包含性校验** —— 冲突的是手段，不是目的。五条规则缺一不可：① 纯文件名 / 相对路径；
② 不含 `/` 与 `\` 分隔符（多文件路径段的 `/` 除外）；③ 不含 `..`（含空段与 `.`）；
④ 不是绝对路径、不带盘符；⑤ **解析后仍位于 `home` 之内**。
适用范围 = 值文件的名称与类型，加上多文件键内嵌路径的左侧。实现落在 `src/onconf/_paths.py`。

**状态**：`已实现（待发版）` ｜ **引用设计文稿**：[`file_support.md` §1.1](../../design/file_support.md)、
[威胁模型 T1](../../security/threat-model.md)

### 1.10 「以 JSON 为主」与主 / 辅后端

JSON 是**主值文件格式**（缺省值、能力最完整、`$schema` 指针的落点），YAML / TOML / `.env`
是**可选后端**，不是并列默认。后端能力差异不因定位而消失：`.env` 是字符串后端、
TOML 没有 `null`、`$schema` 指针只在能吃下成员的后端可用 —— 逐条写在文档里。

**状态**：`已实现（待发版）` ｜ **引用设计文稿**：[`file_support.md` §5](../../design/file_support.md)

### 1.11 求值来源只有两层

`ONCONF_HOME` 只决定配置目录，**不是配置源**。「`.env` 文件后端」（读 `settings.env`）与
「系统环境变量源」（读 `os.environ`，实现里不存在）是两件事，不允许再混称 —— 这处命名
在 `AGENTS.md` / `CONTRIBUTING.md` / `_env_backend.py` 里还没拆干净。求值链路的层数必须与
实现一致，不允许「文档四层、实现两层」并存；**第三层删除还是补齐**要看拍板结果。

**状态**：`已实现（待发版）`（`ONCONF_HOME` 定位不变）；第三层 `待裁`
｜ **引用设计文稿**：（无对应设计文稿）

## 2. 柱二 · 进程结构（独立 Alpha）

### 2.1 Alpha 是独立进程，一个配置目录一个

Alpha 独立于**所有**客户进程，不是客户进程内的线程、也不是客户之一；它是该配置目录
**唯一的读写者**，持有全局声明集与工作集。

**状态**：`待实现` ｜ **引用设计文稿**：**暂无** —— 2.0 的进程结构还没有设计文稿，
本节与下面几条就是口径的落点

### 2.2 自举：关闭制 + 操作系统裁决竞态

启动采**关闭制** —— 默认每个进程都有资格启动，可用参数显式退出该资格；不指定「哪个进程」，
而由 `AutoConf` 入口对象自举（谁先发现 Alpha 不存在就拉起）。启动竞态交给**操作系统的原子
绑定**裁决：只有一个进程能绑上端点成为 Alpha，其余退让并连接，不报错。传输沿用
`multiprocessing.connection`（Windows 命名管道 / POSIX `AF_UNIX`），**不开网络端口**。
Alpha 的启动参数（`home` / `file_type` / 落盘与日志参数 / `identity`）必须经**新的传递路径**
（启动参数或握手）到达 Alpha —— 现有线上协议不携带任何引擎参数。

**状态**：`待实现` ｜ **引用设计文稿**：暂无（见 §2.1）

### 2.3 短命，且端点语义重写

Alpha **不常驻**：多数时间不存在，仅拉起判据成立时出现，那批事务结束即退出。
端点语义：Alpha 在则独占端点、退出即释放；残留端点只在确认无人应答时清理；
裸 `connect` 探测用于判定 Alpha 是否存在，不引入心跳与 PID 判活。客户端 `atexit`
只交出自己的声明并收口日志，**不得关闭 Alpha**；Alpha 也不向 `<home>` 写 PID 或状态文件
（确需新增运行态文件时，必须同步首层路径白名单断言）。

**状态**：`待实现` ｜ **引用设计文稿**：暂无（见 §2.1）

### 2.4 每个请求都有上界，超时就地写

握手沿用 `HELLO_TIMEOUT`，握手之后的 `send` / `recv` 同样加上界 —— 这条是本节其余条款的
落地前提。上界内没等到响应 ⇒ **就地写**（就地写因「运行期不清理未声明的键」而**无损**；
即使 Alpha 活着只是慢，正确性由 OS 锁 + 锁内重读保证）。后续请求继续尝试连接、
在具备资格时重新拉起，一次失败不导致永久放弃。`[Link]` 的 `bind` / `connect` / `fallback`
三态语义按新模型重定。

**状态**：`待实现` ｜ **引用设计文稿**：暂无（见 §2.1）

### 2.5 读路由：写全部收口，读分级

写请求全部经 Alpha 收口；读请求分级 —— 单次读量小由客户自行读文件，量大时转 Alpha 代取。
「小读本地、大读转取」是纯性能选择，不承载正确性。本地读走**指纹检查 + 按需重读**
（值文件与词表的 `mtime` + 大小），不得命中陈旧内存缓存。硬约束：**Alpha 不得持有未落盘的
待提交状态**，收到 `OP_COMMIT` 即当场提交落盘 —— 否则本地读会读到比文件更新的内容，
「文件是事实」就不成立。

**状态**：`待实现`（指纹 + 按需重读已实现）｜ **引用设计文稿**：暂无（见 §2.1）

### 2.6 日志归属发起方，不归执行点

终端形态**回传发起方**、由发起方自己的 `log=` 决定落点（默认 `stderr`）；文件形态由执行点
写进 `<home>/audit.log`。理由是「这个东西本质上就是我的日志」，而 Alpha 没有终端。
Alpha 成为唯一执行点后，「审计文件假定一个执行点」不再成立：`audit.log` 只有一个写入者，
按进程编号的事务号不再交叠。Alpha 自己**不发起写操作**（线上协议只有读与提交两个 op），
所以不存在「没有发起方」的记录场景。

**状态**：`待实现` ｜ **引用设计文稿**：暂无（见 §2.1）

### 2.7 运行期不清理未声明的键

引擎**不删除任何未被代码声明的键**。依据是多进程下必然误删 —— 写者一换人，声明集重置，
新写者按自己那份清理。`reconcile` 不接受清理开关，提交点只做补充、覆盖与元数据更新。
代价：**值文件会随时间积累不再声明的键**，README 一对的已知限制要写明这条。
清理归命令行：`sync` 已交付，单键删除 `remove` 属 2.1+。运行期不清理也是
「就地写无损」的前提。

**状态**：`待实现` ｜ **引用设计文稿**：[`init_config.md` §6](../../design/init_config.md)

### 2.8 安全陈述与威胁模型同步重写

对外陈述是 **「库会拉起一个本机的、只连同用户的 Alpha 进程；不开网络端口、不出机器」**。
禁 import 名单要覆盖 `multiprocessing`，并且不能只按名字检查（`importlib` 能绕过）。
威胁模型相应复核：T4 的残余风险（写者与客户同进程）不再存在，T10「没有网络调用」保持，
T1 与不变量表同步。认证码不是密码学边界 —— 真正的边界是配置目录的文件系统 ACL。

**状态**：`待实现` ｜ **引用设计文稿**：[威胁模型](../../security/threat-model.md)

## 3. 柱三 · 审核日志

### 3.1 两个互不影响的通道

**文件通道**：强制、不可关闭、总是写、紧凑 `key=value`、全量、永不截断。
**终端通道**：可选、可关闭、默认开、带色彩样式、可按级别筛选。
依据是命令行分析日志需要一份恒定完整的数据来源，所以强制性下移到文件那一份。
`log=os.devnull` **只关掉终端那一份**，文件照写。

**状态**：`待实现` ｜ **引用设计文稿**：[`log.md` 目标口径](../../design/log.md)

### 3.2 审计恒写，路径独立参数

`EngineParams` 里**没有 `audit` 开关**；审计文件路径由**独立参数**给，默认
`<home>/audit.log`；`log` 的语义是「终端开关 / 终端去向」。依据是审计文件是否产生
不该取决于一个布尔开关。

**状态**：`待实现` ｜ **引用设计文稿**：[`log.md` 目标口径](../../design/log.md)

### 3.3 级别筛选只作用于终端

取值集合是 `[Read]` / `[Write]` / `[Change]` / `[Error]` 的**任意子集，允许为空**
（终端全静）；文件通道永远全量。级别名是完整词：`[Read]` / `[Write]` / `[Change]` /
`[Error]`，进程结构三行是 `[Start]` / `[Link]` / `[Send]`。

**状态**：`待实现` ｜ **引用设计文稿**：[`log.md` 目标口径](../../design/log.md)

### 3.4 变更事项的判定

`fill` / `register` / `update_meta`（以及命令行侧的覆盖与删除）**计入变更**；
`skip` / `noop` **不计入**；词表变更计入，标记 `scope=vocab`。

**状态**：`待实现` ｜ **引用设计文稿**：[`log.md` 目标口径](../../design/log.md)

### 3.5 终端渲染用 `rich`，必须惰性导入

`rich` 用于**终端人读渲染**，且导入点只在终端渲染分支 —— `import onconf` 不得触碰 `rich`
（实测 `import rich` 要 +180~222 ms，而日志在强制路径上）。作用范围**仅终端通道**：
文件通道仍是紧凑 `key=value`、全量、永不截断、**不含 ANSI**。
**非 TTY 不得输出 ANSI**：判据用 `rich` 的 `Console.is_terminal` 并有测试守护；
非 TTY 走现有纯文本路径、输出与现状逐字一致；日志改到文件时 `stderr` 必须严格为空。
约束是通用规则：**强制路径（`import onconf` 与文件通道）不得多付 `rich` 的导入与渲染成本**。

**状态**：`待实现`（现状无着色、非 TTY 断言已成立；TTY 着色与判据未做）
｜ **引用设计文稿**：（无对应设计文稿）

### 3.6 `rich` 成本数字只留一处

全仓**不重复数值**：要引用就现场重跑实测。数字必须**可复现**：
记录测量脚本、解释器版本、重复次数与基线定义；
倍数必须写明相对哪个基线；无法复现时只写绝对值、不写倍数。这是文档一致性任务，
不改任何导入行为。

**状态**：`待实现` ｜ **引用设计文稿**：（无对应设计文稿）

### 3.7 明文落盘的暴露面定性

明文值是**默认落盘内容**，不需要任何开关，也**不是 opt-in**；加密只改变字节形态，
不改变「未加密时值原样存在」这一事实。既有缓解继续成立：`O_APPEND` 追加、以 `0600` 创建、
字段白名单、键名与身份里的 CR / LF 折成可见转义。文档口径：README 一对写「文件通道恒写、
落盘内容包含真实值」；威胁模型 T12 的缓解列表不含「默认关」；能力表不写 `audit=True` 前缀。

**状态**：`待实现` ｜ **引用设计文稿**：[`log.md` 目标口径](../../design/log.md)、
[威胁模型 T12](../../security/threat-model.md)

## 4. 柱四 · 命令行

命令一览：`build` / `sync` **已实现（待发版）**；本版补 `check` / `format`（仅 JSON）/
`diff` / `read` / `get` / `set`；`add`、`remove`、日志分析视图归 2.1+。

### 4.1 `build` 与 `sync`

差别只在**是否清理**：`build` 按声明完整重建值文件与词表（`--path` 换输出目录、
原目录不动，会丢掉手改内容）；`sync` 补缺 + 删除声明里没有的键（`--no-clean` 只补缺）。
两条都支持 `--dry-run`（一个字节都不写）与 `--json`。判据是**代码里的声明集**，
靠**静态扫描项目里的 `conf(...)` 调用**得到（`ast.parse`，不 import、不执行用户代码）；
扫不动的调用会被逐条列出，此时 `sync` **拒绝删除任何键**并以非 0 退出。
清理归 `onconf sync`（离线、单次、全量，不进多进程执行路径）。

**状态**：`已实现（待发版）` ｜ **引用设计文稿**：[`init_config.md` §6](../../design/init_config.md)

### 4.2 `check`：一个字节都不写

`check` 走专门的**只读路径**：不建 `schema/`、不产生 `audit.log`、不改值文件、不留其它写
句柄 —— CI 会在只读环境或干净工作区里跑它。只读不等于不读：仍读值文件与词表，检查一致性、
`$schema` 指针、后端可解析性与**使用约定**；如需与并发写者互斥，只允许**不创建文件**的读锁。
结果只经 stdout 与退出码表达；只读性写成回归断言（跑完既有文件 `mtime` 与内容不变、
不新增文件与目录）。

**状态**：`待实现` ｜ **引用设计文稿**：[`init_config.md` §8](../../design/init_config.md)、
[§9 还没落地的部分](../../design/init_config.md)

### 4.3 `get` / `read` / `set` / `diff` / `format`

- `read` 取文件级原始数据；`get` 取键级语义值（按词表校验后输出明文）。
- `set` 只改已有键；`add`（创建新键 + 更新词表 + 生成声明代码）归 2.1+。
- `diff` 建立在明确定义的**哈希索引**上（现状审计记录只有 `old=` / `new=`，
  仓库唯一的哈希是声明集指纹，**不是内容哈希**）。
- `format` **只对 JSON** 值文件重排缩进：YAML 缩进是语法、TOML 注释必须保留而标准库只有
  读侧、`.env` 结构扁平无处作用。不带格式化参数时**不修改任何字节**；重排后必须保留
  `$schema` 数据成员与键序。这也顺带消掉了「保注释」难题，不必引入 `ruamel.yaml`。

**状态**：`待实现` ｜ **引用设计文稿**：[`file_support.md` §10](../../design/file_support.md)、
[`init_config.md` §9](../../design/init_config.md)

### 4.4 破坏性操作的形态与统一约定

破坏性命令一律支持 `--dry-run`，只打印将发生的变化、**不写一个字节**；缺省**不是**
`--dry-run`；执行前必须能回答「哪个文件、哪些键、变成什么」。**非 TTY 下禁止任何交互**
（管道与 CI 里交互会永久阻塞）。统一约定还有：每个命令的退出码必须定义（0 成功 /
非 0 按错误分类）；需要机器可读输出的命令提供 `--json`，与非 `--json` **同源**；
`--file X k` 与键内嵌路径 `X:k` 等价，两种写法只在多文件开启时解析路径；
破坏性命令的输出必须提示「目标配置目录可能正在被进程使用」。

**状态**：`待实现`（`--dry-run` / `--json` 两条在 `build` / `sync` 上已实现）
｜ **引用设计文稿**：[`init_config.md` §6](../../design/init_config.md)

### 4.5 破坏性命令不与 Alpha 握手

角色定死：CLI 是配置目录的**管理者**，运行中的进程是**使用者**。管理动作在运行期执行时，
使用者读到的是管理后的结果，而不是崩溃或写了一半的状态（写入是原子替换）。CLI
**不与 Alpha 的内存状态同步**；内存词表变旧不构成误删 —— 运行期不清理未声明的键。
破坏性命令只依靠自己取锁完成写入，**不引入与进程模型的握手**（不要求 Alpha 存在、
不经过 IPC）。角色定义要写进架构页与威胁模型。

**状态**：`待实现`（机制部分已实现）｜ **引用设计文稿**：[威胁模型](../../security/threat-model.md)

## 5. 2.0 不收的

- **落盘形式**（明文 / 纯二进制 / 二进制加密 / 明文加密）与加密参数、**轮转三组参数**
  （落盘规则 / 触发方式 / 轮转方式）→ 2.1+。加密还须先定密钥与算法形态。
- **`.env` 的 `dict` / `list`**（`env_file_dict` / `env_file_list` 两个开关，默认关；
  写入压成字符串、读取只有形如 `{...}` / `[...]` 才尝试解回、解不回返回原字符串）
  → 2.1+（预计 2.2）。
- **`add` / `remove` / 日志分析命令** → 2.1+。
- **数据交付边界**（sink 只收参数不收回调、产出单位是 `Record`）→ 2.1+。
- **设计稿治理**（规格与决策日志分离、口径护栏进 CI）→ 2.1+。
- **命名空间形式 `file_names = []`**、**前缀分片锁**、**按格式导出词表**、
  **把系统环境变量当作配置来源** → 2.1+。
- **WAL（预写日志）** → `不计划`：攒批窗口 + 原子替换 + 只读既存值已经覆盖它要买的东西。
- **`$schema` 指针参数化** → 已定不动：保持按载体能力（能放成员的后端才写）；
  `.env` / `.toml` 上没有落脚点，开了也是空开关。

## 6. 要拍板的问题

按柱子分组。**未定之前对应的那一条不落地**（进程结构尤其如此）。

### 6.1 柱一 · 配置面

- 求值链路第三层（系统环境变量）**删除还是补齐**。现状两层；2.0 暂按「不做」写，等你确认。
- 符号链接的处置：只做字符串与解析后的包含性（现状），还是额外拒绝符号链接。
- 已存在的非普通文件（目录、设备文件）是否一并拒绝。
- 锁粒度：一目录一锁（现状是每个 `(home, file_name)` 一把），还是一文件一锁。
- 键名映射（`.` ↔ `_`、大小写归一化）是否恢复；词表是否按格式分档、是否记录 `origin`。
- `x-onconf-hash` 的处置：删字段 / 接线为写入阶段整体短路 / 改用于变更检测。

### 6.2 柱二 · 进程结构

- **拉起 Alpha 的命令来源**：库内置默认命令，还是配置声明 —— 二选一。
- **「多个事务」的判据**：什么时候拉起 Alpha。必须确定、必须客户侧可判定、
  必须能区分「一个进程连续多次声明」与「多个进程各自在写」。
- 关闭了自启动资格的进程、Alpha 不存在时怎么办。
- 请求上界与启动失败阈值是否复用同一个值。
- 读路由「量大」的口径（多大算大）。
- 运行期不清理未声明的键之后，`sync()` / `flush()` 是否只留一个名字。

### 6.3 柱三 · 审核日志

- `rich` 的自动折行是否禁用、显示宽度归谁算。
- 是否提供值脱敏（`data=` / `old=` / `new=`）。三候选：不提供、哈希、只记长度。

### 6.4 柱四 · 命令行

- 退出码分类表（现状 0 / 1 / argparse 用法错误 2）。
- 哪些命令提供 `--json`。
- `set` 拒绝创建新键，而 API `conf(key, value)` 会创建 —— 保留差异还是对齐。
- `check` 的只读互斥怎么实现；词表缺失 / 过期的报告级别；是否需要一条「检查但不产生」的
  显式声明。
- `check` 的 warning 是否升级为失败的严格开关；「约定」的完整清单、落点与输出形态。
- `format` 的缩进宽度是否可配。
- `diff` 的哈希索引定义：查询时现算，还是审计记录新增内容哈希字段。
- 破坏性命令是否需要显式确认或先备份。
- 无参数调用 `onconf` 的行为。
- 读取加密 / 二进制落盘形式时的密钥入参形式（随 2.1+ 的落盘形式一起定）。

**不在这个清单里的**：2.1+ 能力自己的默认值（落盘规则、轮转触发与轮转方式的默认值、
`.env` 结构化值的编码与转义边界等）随那些能力一起推迟，不阻塞 2.0。
