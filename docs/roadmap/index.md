# 路线图

> 本路线图是**范围与版本的唯一裁决**：定「做什么、按哪套设计、落在哪个版本」，
> 设计与代码都往它收。同一个说法在层间不一致时**改下层**；实测、事故或部署现实证明
> 这里不成立时**改这里** —— 而改这里只有两种动作：**新增条目**，或**撤回条目的
> `决策状态`**（`已定` → `待裁` / `已废弃`，写明理由与影响面）。
>
> **它不宣布现状** —— 卡片里的转述与代码不符时，改的是本页那一行；「现在能用什么」
> 由 [`README.md`](https://github.com/HanYang06/OnConf/blob/main/README.md) 的能力表与
> [`CHANGELOG.md`](https://github.com/HanYang06/OnConf/blob/main/CHANGELOG.md) 回答。
>
> 参与变更决策作者：[@HanYang06](https://github.com/HanYang06)

## 结构说明

- 本页分**上下两块**：`## 路线增量` 收全部条目（唯一事实源），`## 版本分配` 按版本关联条目 ID。
- **路线增量**是增量性质的：新决策随时加上去，完成就打勾。条目按归属层层嵌套（层 → 模块 → 条目）。
- **路线ID**：三位序号（`001`、`002`…），**全局唯一、顺序发号、号不复用**；条目改名不改号。
  编号从 `001` 起只覆盖本页收录的增量：`1.0.0` 已经发布，它的能力记录在
  [1.0.x 路线图](1.0.x/roadmap.md) 里，本页**不回溯**那一页的编号。
- **条目卡片**：每个条目固定六行，缺项留空不删——字段是栏位，不是正文。
  - `决策状态`：`已定` / `待裁` / `未定` / `未来项` / `已废弃`；破折号后接该状态的具体所指。
  - `设计关联文件`：设计口径在哪一页。`docs/` 内用相对链接；仓库根的文件用反引号路径。
  - `分配实现版本`：落在哪个具体版本——`2.0.0` / `2.1.0` / `2.2.0`；未定写 `待定`，
    废弃写 `已废弃`。
  - `具体实现文件`：代码落在哪；尚未建就写明缺哪一层，不写「无」。
  - `关联 issues / PR`：GitHub 编号；`未合` 标注尚未合并的 PR。
- **勾选框**：`- [x]` 表示这条**不在待办里**——收口了，或是废弃了；两种情形靠括号分辨。
  - **收口**：条目名后不加注。
  - **废弃**：曾经定过、现已不再做，且**既无代码也无设计**的条目——**不删**，打勾并在条目名后
    注 `（已废弃）`。留痕是为后人不再重新提一遍。
- **版本分配**：每个版本号下列该版本关联的条目 ID。版本只有两种状态：
  - **已发布**：标题后注 `（已发布）`——写死，此后不再变动。
  - **未落定路线**：标题后注 `（未落定路线）`，或什么都不写（默认即是）。分配仍可调整——
    改分配是**纯增量**（条目只增不减、版本号只增不减），不视为推翻。
  废弃条目汇总在 `### 已废弃`，不占版本号。
