## 0. 本决策的整体口径

`env_file_dict` / `env_file_list` 两个开关的语义在接口面已定（写时压成字符串、读时尝试解回、解不回回落字符串，解回范围只限 `dict` / `list`）。本单元补齐它落地的两端。

- 编码方式与转义边界要有唯一实现点，还必须落在 `.env` 现有值片段规则内（原 ISSUE-028）；
- 开关关闭后的可观察后果要有口径：关闭 = 该能力完全不参与，引擎不因开关关闭而改写用户文件（原 ISSUE-026）；
- 「引擎写过的结构化字符串」是否需要可识别标记，与编码方式强耦合。

## 1. `.env` 的 dict / list 编码格式与转义边界（原 ISSUE-028）

| 原项 | 值 |
|---|---|
| 原类型 / 优先级 / 状态 | 设计变更 / P2 / 部分已定 |
| 原依赖 | ISSUE-002（写压字符串 / 读尝试解回 / 只限 dict-list 的语义）、ISSUE-026（关闭后处置）、ISSUE-003（开关参数位） |
| 原影响面 | `src/onconf/_env_backend.py`、`src/onconf/_textscan.py`、`tests/test_env_backend.py`、`README.md`、`README.zh-CN.md` |
| 原标签 | `area:env` |

### 背景

- 语义已定（ISSUE-002）：开关开启后写 dict / list 压成字符串、读尝试解回、解不回返回字符串，解回范围只限 `dict` / `list` 两种结构。
- 现状 `.env` 后端只接受字符串：`render()` 对非 `str` 抛 `TypeError`（`src/onconf/_env_backend.py:104-110`），`loads()` 一律返回 `str`（`_env_backend.py:167-172`）。
- 值片段的既有规则：含空白 / 引号 / 反斜杠时加双引号，内部转义 `\n \t \r \" \\`；空字符串也加引号（`_env_backend.py:45-55,111-120`）。
- 注释规则：`.env` 刻意不认行内注释，`#` 只在整行时才是注释（`_env_backend.py:15-21,132-152`）；`_textscan.comment_index` 是 YAML / TOML 的规则，`.env` 不走它（`src/onconf/_textscan.py:16-22`）。

不可接受之处：编码方式与转义边界都没有口径，压进去的字符串与用户在文件里手写的字符串无法区分，「尝试解回」的判据也不可验证。

### 结论

1. **触发判据**：只有值形如 `{...}` / `[...]` 才尝试解回，且只有解出 `dict` / `list` 才采用；其余一律原样返回字符串。
2. **写入结果必须落在现有值片段规则内**：编码后的字符串按 `render()` 的既有引号 / 转义规则落到 `KEY=value` 单行结构里，不得让编码结果破坏行结构或跨行（`src/onconf/_env_backend.py:104-120`）。
3. **解回失败不报错**，返回原字符串。
4. **开关关闭时本项不参与**（ISSUE-026）。
5. `render()` 的错误消息与 `README` 必须写出同一套编码口径，不允许各写一份。

### 变更项

| 位置 | 改动 |
|---|---|
| `src/onconf/_env_backend.py:104-120` | `render()` 接受 `dict` / `list`，按定案编码成字符串并走既有引号 / 转义规则 |
| `src/onconf/_env_backend.py:167-172` | `loads()` 对 `{...}` / `[...]` 形态按定案解码，只采用 `dict` / `list` |
| `src/onconf/_env_backend.py:45-55` | 如采纳裸值承载，转义集合与加引号判据同步扩展 |
| `src/onconf/_textscan.py:16-22` | 如改动行内 `#` 取舍，`.env` 与 YAML / TOML 的规则分叉要写清 |
| `README.md:158`、`README.zh-CN.md` | `.env` 后端说明补编码方式、转义边界、解回范围 |
| `docs/roadmap.md` | `.env` 复杂值支持落地后同步状态行 |
| `tests/test_env_backend.py` | 往返测试：dict / list 各种嵌套与特殊字符；解不回回落；手写字面量不被误伤 |

### 验收标准

- [ ] 编码方式有唯一实现点，`render()` 与 `loads()` 用同一套定义
- [ ] 含换行、制表、双引号、反斜杠、`#`、空白的 dict / list 值往返后逐项相等
- [ ] 值文件里手写的普通字符串（如 `'{"a": 1}'` 之外的文本、`[not a list`）不被误判
- [ ] 标量不被解回：`8080` / `true` / `null` 仍是字符串
- [ ] 解回失败返回原字符串且不抛异常
- [ ] 回写只改被触及的字节，注释与键序逐字不变
- [ ] `README.md` 与 `README.zh-CN.md` 同步

### 未决事项

#### 1. 编码方式

| 候选 | 代价 |
|---|---|
| (a) JSON（`json.dumps` / `json.loads`） | 与 JSON 字面量绑定，用户手写的 `{"a": 1}` 也会被解回；JSON 标量（`null` / 数字 / 布尔）必须靠「只采用 dict / list」挡住 |
| (b) Python 字面量（`repr` / `ast.literal_eval`） | 引入 `ast` 依赖面；单引号形态与现有双引号转义规则要重新对齐 |
| (c) 带前缀的自定义标记（如 `@dict:{...}`） | `.env` 里出现引擎私有语法，手写值要与它区分，跨工具（python-dotenv 等）不可读 |

#### 2. 转义边界

| 候选 | 代价 |
|---|---|
| (a) 编码结果整体作为一个双引号字符串，内部按现有规则转义 | 引号嵌套层数随编码方式变化，`render()` 的规则需扩展 |
| (b) 允许裸值承载 `[...]` / `{...}` | 含空格或 `#` 的值会被现有扫描规则截断或误判（`src/onconf/_env_backend.py:132-152`），且与「不认行内注释」的取舍耦合 |

#### 3. 行内 `#` 的取舍是否扩展

| 候选 | 代价 |
|---|---|
| (a) 维持不认行内注释（`src/onconf/_env_backend.py:15-21`） | 编码串里出现 ` #` 时，把 ` #` 当注释的解析器读到的是另一个值 |
| (b) 改为认行内注释 | 密码里带 `#` 的既有用法被破坏，与当前取舍相反 |

## 2. 能力开关关闭后已有产物的处置（原 ISSUE-026）

| 原项 | 值 |
|---|---|
| 原类型 / 优先级 / 状态 | 设计变更 / P2 / 部分已定 |
| 原依赖 | ISSUE-002（`.env` 结构开关的语义）、ISSUE-003（能力开关清单与分层）、ISSUE-028（编码格式） |
| 原影响面 | `src/onconf/_env_backend.py`、`src/onconf/_engine.py`、`tests/test_env_backend.py`、`README.md`、`README.zh-CN.md` |
| 原标签 | `area:env` |

### 背景

- 现存能力开关收口为 `env_file_dict` / `env_file_list` 两个布尔参数（见 ISSUE-002），控制 `.env` 后端能否写入与解回 dict / list 两种结构。
- 原「关掉词表 ⇒ `schema/` 怎么办」的问法随词表锁死消失：词表是核心结构，不是开关（`DESIGN.md:38`），不存在「关掉后产物怎么办」。
- 开关关闭时 `.env` 后端一律返回字符串（`src/onconf/_env_backend.py:167-172`），而文件里可能仍留着先前写入的结构化字符串。
- 写入路径对非字符串一律报错（`src/onconf/_env_backend.py:104-110`）。
- 回写的既定承诺是外科手术式的：未被触及的字节逐字不动（`README.md:46-47`）。

不可接受之处：开关切换后的可观察后果没有口径，文件里的结构化值是保留、改写还是报错无法预知。

### 结论

1. **关闭 = 该能力完全不参与**：不做写入序列化，也不做读取解回。关闭状态下读到结构化字符串就是普通字符串，与「解不回就返回字符串」走同一条路径（ISSUE-002）。
2. **关闭状态下写入 dict / list**：`render()` 拒绝非 `str` 并抛 `TypeError`，错误消息指向 JSON / YAML 值文件（`src/onconf/_env_backend.py:104-110`）—— 这条现有口径保留。
3. **开关属引导层参数**：运行中不可改，改了必须重启（ISSUE-003 §4）。
4. **引擎不因开关关闭而改写用户文件**：关闭本身不产生任何写入动作。
5. 开关的取值与默认值只有一处权威：`EngineParams`（`src/onconf/__init__.py:44-55`）。

### 变更项

| 位置 | 改动 |
|---|---|
| `src/onconf/__init__.py:44-55` | `env_file_dict` / `env_file_list` 进入 `EngineParams`，默认 `False` |
| `src/onconf/_engine.py:273-276` | 后端分派把两个开关传给 `.env` 后端；`.json` / `.yaml` / `.toml` 不受影响 |
| `src/onconf/_env_backend.py:104-110` | `render()` 在开关关闭时维持 `TypeError`；错误消息补上开关名 |
| `src/onconf/_env_backend.py:167-172` | `loads()` 在开关关闭时不尝试解回，路径与「解不回回落字符串」共用 |
| `README.md:127,158`、`README.zh-CN.md` | 参数表与 `.env` 后端说明加入两个开关及其关闭语义（两者是一对） |
| `tests/test_env_backend.py` | 新增：关闭时写 dict / list 报错、关闭时结构化字符串按字符串返回、开关切换前后文件字节不变 |

### 验收标准

- [ ] 开关关闭时 `render()` 对 dict / list 抛 `TypeError`，消息含开关名
- [ ] 开关关闭时读回的结构化字符串与文件字节逐字一致，`loads()` 不做任何解回
- [ ] 开关开启再关闭的往返中，值文件里未被触及的字节逐字不变（含注释、缩进、键序）
- [ ] 关闭状态下的运行不产生任何写入；`mtime` 与内容均不变
- [ ] `README.md` 与 `README.zh-CN.md` 同步

### 未决事项

#### 1. 已有产物在开关关闭后的物理处置

| 候选 | 代价 |
|---|---|
| (a) 保留不动，只是不再解回 | 同一条值在关闭与开启两种状态下读到不同类型；重新打开开关才恢复结构 |
| (b) 首次以关闭状态启动时，把结构化字符串改写回普通字符串 | 开关切换即改写用户文件，与「未触及的字节逐字不动」冲突；无法区分「引擎写过的结构化字符串」与「恰好长这样的普通字符串」 |
| (c) 检测到结构化值且开关关闭时报错 | 一个低风险细节开关变成启动阻塞项，与「该能力完全不参与」相矛盾 |

#### 2. 「引擎写过的结构化字符串」是否需要可识别标记

| 候选 | 代价 |
|---|---|
| (a) 不需要标记 | 手写值与引擎写入值不可区分，候选 (b) 永远无法实现 |
| (b) 需要标记（如编码前缀） | `.env` 里出现引擎私有语法，跨工具不可读；与 ISSUE-028 的编码方式强耦合 |
