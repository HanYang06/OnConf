## 写作约定（发布前删除本节）

1. **一个决策一个文件。** 决定这份文件边界的不是「一个问题」，而是「一次裁定」。判断依据：头尾必须能一起读通，且改动落在同一批文件上。
2. **成员正文逐字保留。** 重组只做三件事：加单元头、加 §0 串联、把成员标题下沉一级并标注原编号。**任何裁定内容都不许在重组里被改写**；要改口径就走新编号。
3. **语言**：正文中文；标识符、路径、字段、命令保持英文原文。
4. **人称**：不使用「你 / 我 / 咱们」；主语用「引擎」「调用方」「本项」「命令」。
5. **只写结果**：不写口述引用、不写对账过程、不写「上一轮 / 本轮 / 留痕 / 倾向 / 建议默认」。
   需要依据时引用 `DESIGN.md` 节号或 `file:line`。
6. **禁 emoji**：`✅ ❌ ⚠ 🎉 🔴 🟡` 等一律不用。
7. **交叉引用**：写 `ISSUE-NNN`（原始编号）或 `DNN`（决策单元）；不写 `#NNN`。
8. **标题层级**：`#` 只出现一次；正文从 `##` 起，不跳级。
9. **代码块标语言**；表格前后空行。
10. **前置必须无环。** 新增单元时，`前置` 只能指向决定发布顺序的单元；口径耦合写进 `联动`。
