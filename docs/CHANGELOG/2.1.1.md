## [2.1.1] - 2026-10-20

### Added

### Changed

- **发布流程**：`v*` tag 推上去、PyPI 发布成功之后，会**自动建 GitHub Release** —— 正文取该
  版本的变更页（相对链接转成绝对链接），再接上 GitHub 原生的 PR / 作者 / 完整对比附录；同时
  多一道闸门：没有 `docs/CHANGELOG/<版本>.md` 的版本发不出去。CI 也新增死链检查：文档里的
  相对链接与指向本仓库的地址必须落到真实路径。
- **发版收口会顺手改 `mkdocs.yml` 的导航**：`scripts/release_notes.py finalize` 现在多干一件事
  —— 把新版本那一页插进「变更日志」导航组。以前它只写版本页、索引与未发布页，导航要人手工补；
  漏一次不是警告，而是 docs job 的 `mkdocs build --strict` 直接红。
- **路线图 2.0.0 与 2.1.0 两节标为「已发布」**：两个版本都已发出去，标题却还挂着「未落定
  路线」。同时把 2.1.0 那批未交付的条目改分配到 2.2.0（`2-036` / `2-037` / `2-039` /
  `2-041` / `2-045` / `2-053` / `2-054` / `2-056` / `2-066` / `2-068` / `2-069`）——
  版本分配只增不减，这次是纯增量的重新归档，条目与编号一个没动。

### Fixed

- **PyPI 页面上的变更日志链接**（`[project.urls]` 的 `Changelog`）指向了一个 404 地址，从本版
  起指向按版本分页的变更日志索引。
- **已发布版本引用过的 2.0.x 路线图页**恢复可达：此前线上是 404。
- **英文 README 还在描述一个 2.0 就已删除的机制**：它说「不丢一次更新」靠**专职写者**
  （Windows 命名管道 / POSIX Unix socket）加跨进程 OS 锁保证，而 IPC 与跨进程锁在 2.0 已整条
  移除，同一份 README 的「已知限制」里还写着引擎不做跨进程协调 —— 两处互相矛盾。现在与中文版
  同源：属主 / 派生角色 + 进程内纯内存锁；顺带把「当前版本」从 `1.0.0` 更新到 `2.1.0`。
- **文档站首页与快速开始还停在 `1.0.0`**：`docs/index.md` 与 `docs/getting-started.md` 让人
  「装 PyPI 上已发布的 1.0.0」，而那已经是一条宣告过破坏性变更的旧线；现在指向 `2.1.0`。
- **两份 README 的命令行一节写着「九条计划命令里已实现两条」**：实际交付七条
  （`build` / `sync` / `check` / `get` / `set` / `diff` / `format`）。同一节的示例也只列了
  `build` / `sync`，现在补齐另外五条。
- **模块布局树漏了 `_boot.py` 与 `_style.py`**，且 `_cli.py` 的注释停在「build / sync」；
  两处都是派生视图，按 `src/onconf/` 的实际清单改正。
- **README 的路线图表把「`add` / `log`」与「按格式导出词表」挂在 `2.1`**：2.1.0 已发布而
  两者都未交付，里程碑随路线图改到 `2.2`。
- **TTY 着色用例不密封**：`tests/test_log.py` 只固定了「是不是 TTY」，没固定 `TERM`。rich 自己
  还会把 `TERM=dumb` / `unknown` 当成 dumb terminal，于是这条用例在带 `TERM=dumb` 的终端里红、
  在 CI 里绿 —— 红的是环境，不是着色。现在用例显式把终端类型固定成支持颜色的一种。
- **标签自动化的两处修复**：`labeler` 的正则放进变量（否则 bash 把它当命令替换）、标签名加
  引号，并且显式告诉 `gh` 仓库是谁。这两处修复此前没有在未发布页留行，本次补上。
- **文档拼写**：一处错字。
